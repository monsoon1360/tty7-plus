An SSH pane runs one shell on a remote machine. A **remote workspace** goes
further: tty7 runs a server on the far machine, and the whole workbench points
at it. Tabs, splits, the file tree, the git panel, the diff overlay, the process
list — all of it is the remote machine's, rendered here.

Nothing is synced or copied. The repository stays where it is.

## Connecting

<Steps>
  <Step title="Open the New Workspace form">
    <kbd>⌘ ⇧ N</kbd>, or the button at the bottom of the switcher
    (<kbd>⌘ ⇧ O</kbd>). The form's host dropdown lists *This Computer*, every
    saved SSH profile, your `~/.ssh/config` aliases and, on Windows, every WSL
    distribution — type to filter when the list is long.
  </Step>
  <Step title="Pick a machine">
    tty7 connects over the same SSH stack as everything else, so profiles,
    keychain credentials, and jump hosts all apply. A machine that is not
    connected yet connects first, then creates the workspace in its home
    directory.
  </Step>
  <Step title="Approve the server install, once">
    The first connection asks:

    > tty7 will write its server binary to *devbox* so this machine can host
    > workspaces there. Nothing else on *devbox* is touched, and no sudo is
    > used.

    It shows the exact path, version, size, source, and SHA-256 before you
    agree. Later upgrades on that machine install silently.
  </Step>
  <Step title="Open a workspace">
    From then on the machine's workspaces sit in the switcher's flat list next
    to your local ones, each row carrying the machine's name and link state,
    and a new one opens like a local one.
  </Step>
</Steps>

## What gets installed

| | |
|---|---|
| **What** | A single self-contained `tty7-server` binary |
| **Where** | `~/.local/share/tty7/bin/tty7-server-c<control>p<protocol>` |
| **Privileges** | None. No sudo, nothing outside your home directory |
| **Hosts** | Linux (x86-64 or aarch64) and macOS (Apple Silicon or Intel) |

The Linux binary is linked fully static against musl, so it runs on any
distribution whatever its glibc vintage. The macOS one links only the libraries
every Mac already has. Either way nothing is installed beside it.

The binary is named after the wire dialect it speaks, so a client and a server
that disagree never quietly half-work — tty7 installs the matching one instead.

On Windows, a WSL distribution is handed the Linux server the installer already
shipped, so a WSL workspace needs no network access at all.

## Reattaching

Remote workspaces are the point at which persistence pays off twice: the panes
survive on the remote machine whether or not your laptop is awake, and you can
reattach from a different client entirely.

A strip along the top of the window says what the connection is doing —
*connecting*, *reconnecting (attempt 3)*, *disconnected*, or *taken over by
someone else*. Reconnection is automatic; a workspace another client has claimed
says so by name rather than fighting over it.

## Deleting a profile

Deleting an SSH profile forgets every local workspace entry that connected
through it. The confirmation names the profile's endpoint and counts the
entries going with it, and the profile's keychain credentials go too. Only the
bookmarks on this computer are touched — the sessions on the remote machine
keep running, and connecting to that machine again under a new profile brings
its workspaces back into the switcher from the machine's own list.

An entry holding a live or in-flight connection is left alone, and parks once
the link drops: it stops reconnecting on its own, keeps the name of the route
that made it rather than falling back to an internal id, and its switcher row
offers **Remove entry**. The sessions behind it are still on the machine,
waiting for a new profile.

## Keeping the server current

Two dialogs you may meet:

<AccordionGroup>
  <Accordion title="Update tty7's server on “devbox”?">
    The machine is serving sessions from a build whose protocol this client
    cannot speak. tty7 has already installed a matching server, but the one
    already running is the one your sessions are on. **Update Server** replaces
    it and **ends every session it is hosting** — including ones this window is
    not showing. Cancel leaves the machine exactly as it is.
  </Accordion>
  <Accordion title="Restart tty7's server on “devbox”?">
    Same consequence, deliberately: every shell on that machine ends. Workspaces
    and layouts are kept and come back with fresh shells.
  </Accordion>
</AccordionGroup>

<Warning>
  Both of these end other people's work if the machine is shared. tty7 spells
  out what will happen before either one runs — read it.
</Warning>

## What a remote pane cannot do

- **Fork an agent session.** The fork command would run against the *local*
  agent, so tty7 does not offer it.
- **Move very large files through the Files panel.** Drag a file onto the tree
  to upload it; right-click a file → **Download** to copy it into this machine's
  Downloads folder (numbered, never overwritten, as in [SFTP](/remote/sftp)).
  Both directions are capped at what one control frame can carry, about 63 MB;
  past that the panel says so and points you at SFTP, `scp` or `rsync`.

## From the CLI

```bash
tty7 machine ls              # this machine plus every link the server holds
tty7 -m devbox ls            # route any command to a linked machine
tty7 -m devbox run -- cargo test
```

`-m` matches the full link key (`me@devbox:22`) or just the host. It uses a link
the local server *already* holds — it will not dial a fresh connection, and it
says so rather than guessing. Connect from the switcher first.

## Android remote terminals

The Android Kotlin Multiplatform Compose app connects to this computer's
background tty7 daemon through a Rust relay. Both computer and phone make
outbound connections; closing the desktop GUI does not stop the daemon or its
shells. This is terminal and session access, not screen sharing: no mouse,
file browser, file transfer or push notifications. Keep the Android app in the
foreground while connected.

### Pair and reconnect

1. On the desktop, open **Settings → Pair Devices**. Configure the relay URL
   and its trusted leaf certificate SHA-256 fingerprint, then enable access.
   The initial empty pin fails closed; it does not trust a self-signed server
   automatically. A pin is exactly 64 hexadecimal characters.
2. Generate a QR code; it expires after five minutes. On Android, grant camera
   permission and scan it. Treat the QR as a temporary secret, not something
   to post or include in logs.
3. Compare the verification code on the phone with the desktop request, then
   approve that device on the desktop. Before approval the phone cannot list
   sessions or send terminal input.
4. Open the left session drawer and select a terminal. The Chinese-first Android
   interface groups sessions with the desktop's repository grouping rules and
   displays branches and Agent status. A loading overlay stays until the selected
   terminal's current screen has been atomically applied by its renderer.
   Synchronization does not focus the keyboard. Tap the terminal without dragging
   to type at its cursor. Tapping focuses input at the application's existing
   cursor; it does not guess an editing position from terminal output. The fixed
   two-row key bar provides **回车** (Enter/CR), **换行** (Ctrl-J/LF) for Codex
   and omp, **Esc**, **Ctrl-C** (中断), and **更多** on the first row, with all
   four direction keys always available on the second row. **更多** contains
   Tab, Home, End and Codex's **Shift+←**. Other programs show the raw **Ctrl-J**
   name, since LF can execute a shell command.
   Opening the workspace drawer clears
   input focus and dismisses the keyboard. Create workspaces and terminals,
   switch between them, or close a terminal after confirming.
   The shared PTY uses the phone's measured grid and adapts when the keyboard changes
   the available height; it is not a horizontally clipped desktop-width terminal.
5. Each phone saves exactly one computer. **扫描与配对管理** opens its pairing
   management screen. Confirm **解除配对** before scanning or opening a pairing link
   for another computer; canceling keeps the current pairing. Migration from an
   older multi-computer store keeps the last approved computer, or the latest
   pending pairing if none is approved.
6. The approved computer reconnects automatically on cold launch and foreground
   return; pairing does not need to be repeated. A foreground network interruption
   keeps the selected terminal behind a reconnect overlay. After reconnection,
   the overlay clears only when its new snapshot is completely parsed. There is
   no separate Disconnect button. Unpairing removes the phone's saved credential;
   **revoke** its device entry on the desktop to withdraw access there. Disabling
   desktop mobile access disconnects live phones and stops relay access.

### Content synchronization and failure handling

The daemon continuously interprets each new PTY with the same terminal engine,
width rules, prompt reflow and cursor repair as the desktop. Protocol 3 sends a
snapshot of **only the visible screen**, then changed rows and cursor/input modes.
This is terminal cell state, not a screenshot image, video, or raw historical ANSI.
The phone paints safe synthesized row instructions; it never resumes the
application's original escape stream from a screen-only reconstruction.

The prewarmed WebView is reused across selections and reconnects. Its measured
geometry is included in the initial subscription, so a phone-sized snapshot can
be produced without first replaying a desktop-width terminal. While its size
lease is held, the phone controls the shared PTY grid; release restores the
desktop grid. Desktop takeback prevents later phone resize requests from
reclaiming control until the terminal is explicitly reopened. Selection and
normal-buffer history positions remain client-local. Alternate-screen applications
such as Codex own their transcript: vertical gestures send mouse-wheel reports,
or cursor keys when the application requests alternate scrolling without mouse
tracking. Terminal-query responses remain the desktop's responsibility.

Local history follows finger travel at 1:1 for precise positioning inside tables
and long output, retains drag distance while its first page loads, and stops
coasting at either boundary. Remote application scrolling coalesces input over
32 ms and sends at most 20 wheel lines per batch without discarding remaining whole
lines. Its shorter coast ends within 240 ms; reversing direction replaces unsent
old-direction movement. A new touch or key cancels pending scrolling and inertia.
Horizontal panning remains 1:1. Pointer capture on the stable viewport keeps
gestures intact when xterm replaces rendered rows. Drags, cancelled gestures and
multi-touch never focus terminal input; only an intentional tap requests the IME.
Screen presentation JSON is prepared off the Android UI thread, and unchanged
screen geometry does not repeat local scroll-to-bottom layout work.

The live renderer stays visible while the first history page is loading; the
history surface is revealed only after that page is completely parsed. Returning
to the bottom cancels the pending reveal and its coast, so a late response cannot
cover the live screen for a frame.

When Codex shows its return-to-latest hint, use **Esc** on the phone's key bar.
The key cancels pending scroll input and inertia before reaching the application.
OMP and ordinary terminals instead also provide **回到底部** beside the local
history status; this returns to the live screen without sending a key or opening
the keyboard. It hides at the bottom and appears after scrolling away, even if
background output advances while history is open. A truncated-window boundary
is not the live bottom. Codex does not show this local-history button.
The history toolbar keeps the same height when its return button appears or
disappears, so reaching the bottom does not move the rows underneath it.
Esc is not “close terminal”:
the application decides whether it cancels a dialog, returns to latest output,
or stops a turn. Ctrl-C is a separate interrupt input. **换行** sends LF rather
than Enter/CR; Codex and omp use it for message newlines, while a shell or another
program may interpret it differently. Closing a terminal remains a separate,
confirmed action.

The dark terminal sets explicit light text and cursor colours and enforces a
4.5:1 minimum text contrast for ANSI/truecolour output, so a desktop application's
dark text remains readable on the phone.

Every subscription has its own generation and ordered frame sequence. Screen
revisions and geometry/buffer epochs are decimal strings; patches identify the
exact base revision they replace. Geometry changes and normal/alternate-buffer
transitions require a complete replacement. A mismatched base requests a fresh
screen instead of applying a potentially stale patch.

Frames are at most 128 KiB, with at most 8 MiB staged for one logical screen and
four frames awaiting credit. Android acknowledges intermediate parts only after
bounded staging; the final part is acknowledged after the complete state has
been applied by the terminal parser. That commit releases the loading overlay.
Old-generation callbacks cannot acknowledge or reveal another selection. When
credit stalls, the producer samples the latest immutable screen after it can
send again, rather than accumulating a raw-output backlog.

History is a separate, read-only surface opened by upward scrolling:

- The primary buffer retains at most 5,000 rows and an 8 MiB history budget.
  It remains available during an alternate-screen application; the alternate
  screen does not acquire invented scrollback.
- A history request captures retained rows and their adjoining normal screen in
  one immutable view, then pages backward through it using opaque cursors. A
  separately timed live screen is never spliced onto that view. New output and
  resize/reflow cannot move those cursors. With no retained rows, history remains
  empty. Update both the Android app and desktop daemon for this behavior.
  Each page is at most 200 rows / 128 KiB; the host retains at most 16 views /
  32 MiB and permits two history workers. An active view does not expire merely
  because the reader pauses. Subscription teardown releases it; the global
  view-count and byte limits still evict the oldest windows under pressure.
- History preserves the shared terminal's current grid width. Soft-wrapped rows
  are not joined into desktop-width lines: the phone does not expand its terminal
  or history width to make old desktop tables fit. Applications receive the
  phone's measured PTY size and own any content reformatting after that resize.
- Android retains a continuous window of at most 2,000 rows / 2 MiB of UTF-8 row
  content. A bounded page is parsed in one batch without creating another visible
  terminal renderer. Prepending older rows preserves the reading anchor. If newer
  rows leave the cache, an explicit boundary and **查看较新历史** reload action
  replace them; they are not silently omitted between old and live output.
  This local boundary is distinct from the host's oldest retained-history limit.
- Live screen patches continue while history is open. Returning to the live end
  shows the already-current screen. Reopening history after a live revision
  change obtains a new immutable view instead of joining an old cache to it.
  Loading failures keep the existing window visible; returning live and reopening
  history starts a new view after a cursor is invalidated or its window is evicted.

Clearing a screen no longer makes entry wait for the retained history behind it.
Initial transfer cost follows the current grid rather than the number of old
repaints. For device latency measurements, distinguish connection/authentication,
subscribe, first-screen arrival and renderer commit; a fast local transfer alone
does not establish end-to-end phone latency.

Live output and Agent status are streamed continuously. Agent snapshots carry
monotonic per-pane revisions so older polls or replay cannot replace newer status.
Workspace, title and branch metadata refresh every two seconds, including while
a terminal is open. Agent status uses the desktop's state source; agents that need
status hooks still need those hooks installed. Update the OMP hook and reload it
or start a new Agent session: a running session retains its previously loaded hook.
Subagent completion and automatic continuation do not finish the root Agent turn.
Pi-family hooks also report main-session tool completions: otherwise an active
long turn with no new start/end event can hit the daemon's 30-minute silent-turn
expiry and incorrectly appear idle.
Observer or renderer failures retain the selected terminal and show an error with
**Retry loading**, rather than returning to the QR screen or silently changing sessions.

Update both the Android app and desktop daemon for protocol 3; mismatches report
an explicit update requirement, with no protocol-2 replay fallback. Existing
pairing credentials and certificate pins remain valid.

The first upgrade cannot recover a complete interpreter from a legacy truncated
ring. Such panes are **not automatically restarted**: their desktop processes
continue, while mobile entry explicitly reports unavailable authoritative state.
Finish and reopen those panes manually when appropriate; retrying the same
legacy pane cannot recreate the missing state. Newly created panes start their
mirror before the first PTY byte. Subsequent Unix PTY exec handoffs freeze the
read boundary and preserve both grids, saved cursors, palette/modes, partial
UTF-8/escape sequences and shell/cursor repair state. This guarantee concerns
PTY-backed panes, not native SSH cipher sessions that cannot survive exec.

The phone reconnects while foregrounded; this is not a background keep-alive
service or push channel.

### Trust and credentials

Production connections require native TLS (`wss://`); unencrypted WebSocket
connections are only for loopback development (the Android debug emulator also
allows its host bridge). Configure your own relay address, for example
`wss://relay.example.invalid:8443/v1/ws`, and the SHA-256 fingerprint of its leaf
certificate. The example hostname is reserved and does not identify a deployment.
No deployment address or certificate fingerprint is bundled as a trusted default;
new credential stores start disabled with no pin. Existing saved configuration
and approved devices are not replaced by these defaults.

Obtain the expected pin through a trusted, out-of-band channel before configuring
it. TLS pinning protects the relay connection; end-to-end encryption separately
keeps terminal payloads opaque to the relay. Pairing bootstraps HKDF-derived,
directional AES-256-GCM keys with strict sequence checking to reject replay.
The desktop stores remembered secrets in a private credential store, not
general settings; Android encrypts them using Android Keystore.

When rotating the certificate, distribute the new desktop pin out of band,
revoke the old device entry, and rescan and approve each phone with a fresh QR.
Never commit certificates, private keys, pairing QR data or device credentials
to the repository.

### Build and deploy

For a full Rust workspace build, use **Rust 1.95**: the current upstream GPUI
dependency uses `cold_path`. From the repository root:

```bash
cargo +1.95.0 build --release --workspace
```

For a relay-only release build:

```bash
cargo +1.95.0 build --release -p tty7-relay
```

For Android, install **JDK 17** and **Android SDK 35**, set `ANDROID_HOME` to
the SDK directory, and run this from `mobile/`:

```bash
./gradlew :app:assembleDebug
```

Install the resulting `mobile/app/build/outputs/apk/debug/app-debug.apk` on an
Android 8.0/API 26 or newer device.

For a Linux relay deployment or redeployment, build the release binary above,
install `target/release/tty7-relay` as `/opt/tty7-relay/tty7-relay`, and provision
the certificate and private key privately on the server as
`/opt/tty7-relay/tls.crt` and `/opt/tty7-relay/tls.key`. Use the existing
`scripts/relay/tty7-relay.service` as the systemd unit: it listens on port 8443,
runs with `DynamicUser`, and supplies TLS files through `LoadCredential`.
Restrict the private key to the server administrator; do not store it in a
checkout. Install the unit under `/etc/systemd/system/tty7-relay.service`, then:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tty7-relay.service
# After replacing the binary or TLS credentials:
sudo systemctl restart tty7-relay.service
```

relay health; check it using the trusted certificate/pin rather than disabling
